# 编译真相 + 时间线模式

## 目标

每个大脑页面有两个区域：编译真相（当前综合，随着证据变化而重写）和时间线（仅追加证据轨迹，永远不编辑）。

## 用户得到什么

没有这个：大脑页面是仅追加日志。要理解一个人，你阅读 200 个时间线条目。答案埋在第 147 个条目中。

有了这个：编译真相让你在 30 秒内了解游戏状态。时间线是证据。六个月的条目压缩成一个段落评估，始终是最新的。

### 更新页面

```
update_brain_page(slug, new_info, source):
  page = gbrain get {slug}

  # 时间线：始终追加（永远不要编辑现有条目）
  gbrain add_timeline_entry {slug} {
    date: today,
    summary: new_info.summary,
    detail: new_info.detail,
    source: format_source(source)  // [来源：谁、频道、日期时间时区]
  }

  # 编译真相：重写（不是追加）
  # 读取现有的编译真相
  # 整合新信息
  # 写入更新的综合
  updated_truth = rewrite_compiled_truth(page.compiled_truth, new_info)
  gbrain put {slug} {
    compiled_truth: updated_truth,
    # 时间线不传递 -- 它由 add_timeline_entry 管理
  }
```

### 规则

| 区域 | 操作 | 解释 |
|------|--------|-------------|
| 编译真相 | **重写** | 当前综合。证据变化时改变。 |
| 时间线 | **追加** | 证据轨迹。永远不编辑，只添加到。 |

**每个编译真相声明必须追溯到时间线条目。** 如果评估说"内部评价不足"，应该有支持该声明的时间线条目。

## 棘手的地方

1. **重写意味着重写，不是追加。** 不要向编译真相添加新段落。用整合了新信息的完整章节重写。不再准确的旧评估应该更新，而不是与矛盾的新评估保持在一起。

2. **时间线条目是不可变的。** 永远不要编辑时间线条目。如果信息被证明是错误的，添加一个新的条目来纠正它：
   `- 2026-04-10 | 纠正：Sarah 是工程副总裁，不是 CTO。之前的条目是错误的。`

3. **GBrain 搜索对编译真相的权重更高。** `gbrain query` 返回编译真相块的权重高于时间线块。这意味着最新的综合首先出现在搜索结果中。

4. **--- 分隔符很重要。** GBrain 使用 frontmatter 之后的第一个独立 `---` 来将 compiled_truth 与时间线分开。上面的一切都是编译真相，下面的一切都是时间线。

5. **不要跳过评估部分。** 评估就是价值。"强大的技术领导者"是任何 API 都无法提供的。这是你对此人的解读。这就是让大脑页面比 LinkedIn 更好的原因。

## 如何验证

1. **更新人物页面。** 添加新的会议信息。检查：编译真相被重写（不是追加），时间线在顶部有新的条目。
2. **搜索此人。** `gbrain query "Sarah Chen"`。编译真相（当前综合）应该首先出现，而不是随机的时间线条目。
3. **检查可追溯性。** 编译真相中的每个声明都应该有相应的时间线条目。阅读两个章节并验证。
4. **检查不可变性。** 更新后，旧的时间线条目应该保持不变。日期、来源和内容应该与原始内容完全匹配。
