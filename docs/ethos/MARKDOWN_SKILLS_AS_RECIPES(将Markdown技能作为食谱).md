# 个人 AI 的家酿

`brew install` 给你别人的二进制文件。`npm install` 给你别人的源代码。两者都需要你理解工具、配置它、集成它、维护它。

如果软件分发方式不同呢？如果你能用简单的英语描述一个功能，将这个描述交给 AI 代理，然后代理构建一个根据你的设置量身定制的原生实现呢？

这就是当 markdown 成为代码时发生的事情。

## Markdown 是代码

这是一个真实的技能文件。这个教 AI 代理筛选电话呼叫：

```markdown
# 语音代理 — 你的电话号码

呼叫者 → Twilio → <Stream> WebSocket → 语音服务器（端口 8765）
                                            ↕ 音频
                                      OpenAI Realtime API
                                            ↓ 工具调用
                                      大脑 / 日历 / Telegram

## 呼叫路由

每个呼入电话基于呼叫者电话号码 + 大脑查找进行路由：

### 所有者 → 认证模式
- 发送加密随机的 6 位数字代码到安全通道
- 呼叫者读回代码
- 匹配 → 完整助手模式（大脑、日历、调度）
- 不匹配 → 视为未知呼叫者

### 已知人员，内圈（大脑分数 ≥4）→ 转接
- 用大脑上下文按名字问候
- 转接到手机
- 如果没有应答（30秒超时），留言
- 发 Telegram 消息告知谁来电及上下文

### 未知呼叫者 → 筛选
- 获取他们的名字，在大脑中查找
- 如果是内圈 → 提供转接
- 否则 → 留言
- 创建带电话号码的大脑条目（标记为未验证）
```

这不是伪代码。这不是文档。这是一个可工作的规范，像 Claude Opus 4.6 这样具有百万 token 上下文窗口的模型可以读取并实现。架构图告诉它组件。路由表告诉它逻辑。安全模型告诉它约束。代理读取这个文件，理解它，并构建 Twilio 集成、WebSocket 服务器、Telegram 机器人钩子、大脑查找，所有这一切，都根据你的用户已有的基础设施进行塑造。

技能文件是方法调用。它接收参数（你的电话号码、你的大脑、你首选的消息应用）。相同的技能，不同的参数，不同的实现。过程是包。模型是运行时。

## 分发机制

传统的包管理器分发制品：编译的二进制文件、源 tarball、容器镜像。消费者运行别人的代码。

GBrain 分发食谱：markdown 文件，用足够的特异性描述功能，使 AI 代理可以从头实现它们。消费者获得原生实现。没有依赖地狱。没有版本冲突。没有传递漏洞链。因为没有上游代码。只有关于构建什么和为什么的描述。

它是这样工作的：

1. **构建功能。** 实现语音代理、会议摄取管道、电子邮件分类系统、投资尽调工作流， whatever。

2. **GBrain 捕获食谱。** 不仅仅是代码。架构、集成点、失败模式、判断调用。一个编码完整功能的 markdown 文件。

3. **推送到仓库。** 开源。任何人都可以读取它。

4. **别人的代理拉取食谱。** 读取 markdown。说："新食谱可用：带呼叫筛选的 AI 语音代理。想要吗？" 用户说是。代理读取规范并构建它。

没有安装。没有配置向导。没有 README。代理读取文档并弄清楚。

## 为什么现在有效

两年前这不起作用。两件事改变了。

**上下文窗口达到一百万 token。** 一个真实的会议摄取技能文件有 200+ 行。调用它的丰富技能引用大脑模式、解析器、引用标准、五个外部 API 和交叉链接协议。实现这个食谱的代理需要同时将所有这些保存在工作内存中，同时还要理解用户现有设置。在 8K token 时，不可能。在 128K 时， marginal。在 1M 时，舒适。

**模型跨越了判断阈值。** 这是来自真实丰富食谱的片段：

```markdown
## 哲学

大脑页面应该读起来像情报档案与治疗师笔记的结合，而不是 LinkedIn 爬取。我们想要：

- 他们相信什么 — 意识形态、世界观、第一性原理
- 他们在构建什么 — 当前项目，下一步是什么
- 什么激励他们 — 野心驱动因素、职业弧线
- 什么让他们情绪激动 — 愤怒、兴奋、防御、自豪
- 他们的轨迹 — 上升、平台期、 pivot、下降？
- 硬事实 — 角色、公司、资金、地点、联系信息

事实是赌注。纹理是价值。
```

实现这个食谱的模型必须理解 LinkedIn 爬取和情报档案之间的区别。这是关于什么信息值得捕获以及如何权衡它的判断调用。GPT-3 做不到这一点。GPT-4 可以某种程度上做到。Opus 4.6 做得很好。使能技术是足够聪明的模型来解释意图，而不仅仅是遵循指令。

## 食谱实际包含什么

一个好的食谱有五个部分：

**架构。** 组件图。什么与什么对话，通过什么协议，什么数据流。这是代理首先构建的骨架。

**路由逻辑。** 决策树。当 X 发生时，做 Y。当 Z 失败时，回退到 W。这是领域知识所在。语音代理食谱编码呼叫路由。尽调食谱编码如何处理 pitch deck vs. 财务模型 vs. 股权表。会议摄取食谱编码如何将原始转录变成可操作的情报。

**集成点。** 这个接触什么外部系统？Twilio、Telegram、Gmail、Circleback、Slack、GitHub、Supabase，whatever。食谱命名集成；代理弄清楚如何根据给定的用户已经配置的东西连接它们。

**判断调用。** 困难的部分。不是"发送电子邮件"而是"根据发送者重要性、时间敏感性以及是否需要决策来决定这封电子邮件是否值得引起用户注意"。跳过判断调用的食谱产生浅层实现。判断调用是实际价值。

**失败模式。** 什么出错以及如何处理它。"如果 Circleback token 过期，消息用户并要求他们重新连接。不要静默跳过。""如果呼叫者 ID 被欺骗，永远不要信任它进行身份验证。通过单独通道使用质询-响应代码。" 没有失败模式的食谱产生脆弱系统。

这是一个真实的例子。这是尽调食谱的检测逻辑：

```markdown
## 检测

通过以下方式识别数据室材料：
- PDF 文件名："数据 Deck"、"介绍 Deck"、"股权表"、
  "财务模型"、"Pitch Deck"、"系列 [A-D]"
- 带有选项卡的电子表格：收入、保留、队列、
  CAC、毛利率、单位经济学、ARR
- 用户说："数据室"、"尽调"、"deck"、"pitch"
- 上下文：在尽调主题中共享
```

这是用英语表达的模式匹配器。代理读取这个并知道如何对传入文档进行分类。没有正则表达式。没有文件类型配置。只是对模式的描述和模型关于给定文档是否匹配的判断。

## 挑选和选择

GBrain 不是单体的。食谱是独立的。拿你想要的：

- **语音代理** — 电话筛选、呼叫者 ID、大脑查找、消息路由
- **会议摄取** — 转录处理、实体提取、行动项捕获、时间线更新
- **电子邮件分类** — 收件箱扫描、优先级分类、草稿回复、调度提取
- **丰富管道** — 来自多个数据源的人和公司研究，日记化到大脑页面
- **尽调处理** — 数据室摄取、PDF 提取、财务模型分析
- **社交监控** — X/Twitter 时间线分析、提及跟踪、叙事检测
- **内容管道** — 想法捕获、链接摄取、文章摘要

每个食谱是自包含的。你的代理知道你已经拥有什么。GBrain 每天 ping："自上次同步以来有 3 个新食谱。想要任何吗？" 你挑选。它构建。

因为源代码是英语，fork 是微不足道的。不喜欢语音代理如何处理未知呼叫者？编辑 markdown。将"留言"更改为"先问三个筛选问题"。行为改变是因为规范改变了。

## 薄工具 harness，胖技能的连系

这篇文章是续集。前传是"Thin Harness, Fat Skills"，它认为 100x AI 生产力的秘密不是更好的模型，而是更好的上下文管理。保持 harness 薄（运行模型的程序）。让技能变胖（编码判断和过程的 markdown 过程）。

"Markdown 是代码"是分发推论。如果技能是胖 markdown 文件，并且如果模型足够聪明可以从 markdown 实现，那么技能是可分发的软件。技能文件同时是：

- **文档** 供人类阅读
- **规范** 供实现代理
- **包** 供分发系统
- **源代码** 供结果功能

四种制品折叠成一个。这就是为什么这与以前的每个包管理器都不同。`brew install` 将公式与二进制文件与文档与源代码分开。GBrain 折叠它们。Markdown 是所有四个。

## 底层架构

三层，与谈话相同：

**胖技能** 在顶部。Markdown 食谱编码判断、过程、失败模式和领域知识。这是 90% 价值所在。这是分发的内容。

**薄工具 harness** 在中间。运行模型的程序。文件操作、工具调度、上下文管理、安全执行。大约 200 行。OpenClaw 或任何等效物。harness 约束越少，食谱可以表达的越多。

**确定性基础** 在底部。数据库、API、CLI。相同输入，相同输出，每次。SQL 查询、HTTP 调用、文件读取。技能描述何时调用这些；harness 执行它们。

将智能向上推入技能。将执行向下推入确定性工具。分发技能。这就是整个系统。

## 这意味着什么

当实现成本接近零时，瓶颈转移。不再是"我们能构建这个吗？" 而是"我们应该构建这个吗？"和"它到底应该做什么？"

品味、愿景和领域知识成为稀缺资源。深刻理解呼叫筛选并编写精确食谱的人比能够从头实现 Twilio 集成的人创造更多价值。食谱就是实现。

这也意味着最好的 AI 代理设置将默认为开源。封闭的、专有的代理配置正在与这样一个世界竞争：有人发布食谱，一千个代理在一夜之间实现它。食谱以 git push 的速度传播。护城河是品味，不是代码。

软件分发重新构想：包是 markdown 文件，运行时是足够聪明的模型，包管理器是你的 AI 代理，应用商店是 git 仓库。

`gbrain install voice-agent`

就这样。
