# 起源故事

GBrain 起源于构建 OpenClaw —— Garry 的个人 AI 代理分支。第一版有技能和大脑，但大脑是扁平的 markdown 文件目录。搜索用的是 ripgrep。记忆只是一种感觉。

几乎立即就出现了两个问题。

首先，代理在对话之间会忘记事情。每个新会话都会重新问基本问题。上周介绍的人的名字消失了。周二做的决定活不到周四。大脑存在，但代理实际上无法使用它。

其次，代理不断重复工作。关于同一家公司的两个不同信号变成了两个不同的人页面。与同一个人的三次会议变成了三个不相关的时间线条目。信噪比实时衰减。

GBrain 就是你决定这两件事都不可接受时构建的东西。

修复方法不是一个大创意。而是许多小创意层层叠加：

- 在任何外部 API 调用之前优先进行大脑查找。
- 每次页面写入时自动链接，让图表免费增长。
- 类型化边，这样"谁在 Acme AI 工作？"才能真正返回结果。
- 混合搜索，因为仅靠向量搜索效果不够好。
- 再排序层，因为混合搜索在局部是最优的，但在全局是次优的。
- 夜间 cron 任务去重、丰富、修复引用、发现矛盾。
- 一个代理读取 `skills/RESOLVER.md` 一次就知道该做什么。

这些都不是新颖的想法。贡献在于将它们全部一起发布，运行在 Postgres + pgvector 上（可以在 WASM 中运行，无需服务器），技能是 markdown（不是代码），由一个小文本文件路由（不是路由器 LLM）。

生产大脑已经运行了几个月。17,888 个页面。4,383 个人。723 家公司。21 个自主运行的任务。它让 Garry 醒来时比前一天更聪明。

GBrain 就是你写出你真正想要拥有的大脑时发生的事情。
