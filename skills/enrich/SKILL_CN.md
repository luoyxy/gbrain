# 丰富技能

从外部来源丰富人员和公司页面。根据重要性调整工作量。

## 合约

此技能保证：

- 每个丰富的页面都有带有内联引用的编译真相（状态部分）
- 每个丰富的页面都有带有日期条目的时间线
- 反向链接是双向创建的
- 分层丰富：层级 1（完整）、层级 2（中等）、层级 3（最小），基于显著性
- 无存根：每个新页面都有来自网络搜索或现有大脑上下文的有意义内容

> **归档规则：** 在创建任何新页面之前阅读 `skills/_brain-filing-rules.md`。
>
> **约定：** 参见 `skills/conventions/quality.md` 了解铁律反向链接。
>
> 每个提到有大脑页面的人员或公司的提及都必须从该
> 实体的页面创建反向链接到提到它们的页面。未链接的提及是
> 损坏的大脑。参见 `skills/_brain-filing-rules.md` 了解格式。

## 哲学

大脑页面应该读起来像情报档案，而不是 LinkedIn 抓取。
事实是桌面筹码。纹理是价值——他们相信什么，他们正在
构建什么，什么让他们运作，他们要去哪里。

## 引用要求（强制性）

> **约定：** 参见 `skills/conventions/quality.md` 了解引用格式和来源优先级。
>
> 当来源冲突时，注意两个引用之间的矛盾。

## 何时丰富

### 主要触发器

- 用户在对话中提及实体
- 实体出现在会议记录或电子邮件中
- 新联系人出现带有重要上下文
- 实体上新闻或有重大事件
- 任何摄取管道遇到显著实体

### 不要丰富

- 没有关联系信号的随机提及
- 机器人/垃圾邮件帐户
- 与用户工作没有实质性联系的实体
- 过去一周内以相同页面丰富的（除非新信号保证）

## 丰富层级

根据重要性调整丰富度。不要将 API 调用浪费在低价值实体上。

| 层级 | 谁 | 工作量 | 来源 |
|------|-----|--------|---------|
| 1（关键） | 内圈、密切合作者、关键联系人 | 完整管道 | 所有可用 API + 深度网络研究 |
| 2（显著） | 偶尔互动、行业人物 | 中等 | 网络研究 + 社交 + 大脑交叉引用 |
| 3（次要） | 值得跟踪，不关键 | 轻量 | 大脑交叉引用 + 如果句柄已知则社交查找 |

## 丰富协议（7 步骤）

### 步骤1：识别实体

从传入信号中提取人员、公司、概念。

### 步骤2：检查大脑状态

对于每个实体：
- `gbrain search "姓名"` —— 页面是否已存在？
- **如果是：** 更新路径（添加新信号，如果实质性则更新编译真相）
- **如果否：** 创建路径（首先检查显著性门控，然后创建）

### 步骤3：从来源提取信号

不要只是捕获事实。捕获纹理：

| 信号类型 | 提取什么 |
|-------------|----------------|
| 观点、信念 | 他们相信什么部分 |
| 当前项目、已发布功能 | 他们正在构建什么部分 |
| 野心、职业弧线、动机 | 什么激励他们部分 |
| 他们反复回归的主题 | 爱好马部分 |
| 他们放大、争论、尊重的人 | 网络 / 关系 |
| 上升、平稳、转向？ | 轨迹部分 |
| 角色、公司、资金、位置 | 状态部分（硬事实） |

### 步骤4：外部数据源查找

优先级顺序——当您有足够用于实体层级的信号时停止。

**4a. 大脑交叉引用（总是，所有层级）**
- `gbrain search "姓名"` 和 `gbrain query "我们对姓名了解什么"`
- 检查相关页面：用于人员丰富的公司页面，反之亦然
- 这是免费的，通常是最丰富的来源

**4b. 网络研究（层级 1 和 2）**
- 使用 Perplexity、Brave Search、Exa 或等效的网络研究工具
- **关键模式：** 发送现有大脑知识作为上下文，以便搜索
  返回 DELTA（新的 vs 你已经知道的），而不是重新哈希
- 用于层级 1 深度研究的 Opus 级模型，用于层级 2 的较轻模型

**4c. 社交媒体查找（所有层级当句柄已知时）**
- 拉取最近的帖子/推文以获取语气、兴趣、当前焦点
- 社交媒体是某人实际思考内容的最高纹理信号

**4d. 人员丰富 API（层级 1）**
- LinkedIn 数据、职业历史、连接、教育

**4e. 公司丰富 API（层级 1）**
- 公司数据、财务、人员数、关键招聘、最近新闻

| 数据需求 | 示例来源 | 层级 |
|-----------|----------------|------|
| 网络研究 | Perplexity、Brave、Exa | 1-2 |
| LinkedIn / 职业 | Crustdata、Proxycurl、People Data Labs | 1 |
| 职业历史 | Happenstance、LinkedIn | 1 |
| 资金 / 公司数据 | Crunchbase、PitchBook、Clearbit | 1 |
| 社交媒体 | 平台 API、网络抓取 | 1-3 |
| 会议历史 | 日历/会议记录工具 | 1-2 |

### 步骤5：保存原始数据（保留来源）

通过 `put_raw_data` 在 gbrain 中存储原始 API 响应：

```json
{
  "source": "crustdata",
  "fetched_at": "2026-04-11T...",
  "query": "jane doe",
  "data": { ... }
}
```

原始数据保留来源。如果编译真相受到质疑，
原始数据显示 API 确切返回的内容。

### 步骤6：写入大脑

#### 创建路径

1. 检查显著性门控（参见 `skills/_brain-filing-rules.md`）
2. 检查归档规则——此实体去哪里？
3. 使用适当的模板创建页面（如下）
4. 用引用填充编译真相
5. 添加第一个时间线条目
6. 将空部分保留为 `[No data yet]`（不要用样板填充）

#### 更新路径

1. 添加新的时间线条目（ reverse-chronological，仅附加）
2. 仅当新信号实质性地改变图片时更新编译真相
3. 用新事实更新状态部分
4. 标记新信号和现有编译真相之间的矛盾
5. 不要用 API 样板覆盖用户撰写的评估

```markdown
# 全名

> 1 段执行摘要：如何认识他们，为什么他们重要，
> 关系当前状态是什么。

## 状态
角色、公司、关键上下文。仅硬事实。

## 他们相信什么
意识形态、第一原则、世界观。他们在什么山上死？

## 他们正在构建什么
当前项目、最近发布、他们专注什么。

## 什么激励他们
野心、职业弧线、什么驱动他们。

## 爱好马
他们反复回归的主题。他们工作/帖子中的反复出现的主题。

## 评估
你对此人的解读。优势、差距、轨迹。

## 轨迹
上升、平稳、转向、下降？他们去哪里？

## 关系
互动历史、共享上下文、关系质量。

## 联系人
电子邮件、社交句柄、首选沟通渠道。

## 网络
关键连接、共同联系人、组织关系。

## 开放线程
活跃对话、待处理项目、要跟进的事项。

---

## 时间线
Reverse-chronological。每个条目都有日期和 [来源: ...] 引用。
- **YYYY-MM-DD** | 事件描述 [来源: ...]
```

### 步骤7：交叉引用

- 从人员丰富更新公司页面（反之亦然）
- 如果相关上下文呈现，更新相关项目/交易页面
- 如果大脑使用它们，检查索引文件

**注意（v0.10.1）：** 大脑页面之间的链接在每次
`put_page` 调用时自动创建（自动链接后钩）。步骤7 专注于内容
交叉引用（用来自此丰富的新信号更新相关页面的编译真相），
而不是创建链接。通过 `put_page` 响应中的 `auto_links`
字段验证（包含 `{ created, removed, errors }`）。
时间线条目仍需要显式的 `gbrain timeline-add` 调用。

## 批量丰富规则

- **首先在 3-5 个实体上测试。** 读取实际输出。检查质量。
- 仅在测试镜头通过你的质量栏后继续批量。
- 3+ 来自一个来源 → 批次处理或生成子智能体
- 节流 API 调用。尊重速率限制。
- 在批量运行期间每 5-10 个实体提交一次。
- 批量丰富后保存报告（参见下面的报告存储）。

## 验证规则

- LinkedIn 上的连接数 < 20 = 可能是错误的人，跳过
- 大脑和 API 之间的姓名不匹配 = 跳过，标记以供审查
- 玩笑资料或明显错误的数据 = 保存到原始数据，不要更新页面
- 不要用 API 样板覆盖用户撰写的评估
- 当有疑问时：保存原始数据但不要更新大脑页面

## 报告存储

批量丰富扫描后，保存报告：

- 处理的实体数
- 创建的新页面 vs 现有更新
- 调用的数据源和结果质量
- 显著发现或矛盾
- 验证标志或 API 失败

这创建了随时间的大脑丰富审计线索。

## 反模式

- 创建没有内容的存根页面
- 不首先检查大脑就丰富
- 用 API 数据覆盖用户的直接陈述
- 为非显著实体创建页面

## 输出格式

丰富的人员页面包含：
- 带有类型、标签、公司、关系、联系字段的**前言**
- **执行摘要**（1 段：如何认识他们、为什么他们重要、关系状态）
- 带有硬事实和内联 `[来源: ...]` 引用的**状态**部分
- **纹理部分**（他们相信什么、他们正在构建什么、什么激励他们、爱好马）
- 带有轨迹读取的**评估**
- **关系**历史和联系信息
- **网络**连接和共同联系人
- **时间线**按 reverse-chronological 顺序，每个条目带有日期和引用

丰富的公司页面包含：
- 带有类型和标签的**前言**
- **执行摘要**（1 段）
- **状态**部分（他们做什么、阶段、关键人员、指标、你的连接）
- **开放线程**（活跃项目、待处理决策）
- **时间线**按 reverse-chronological 顺序，带有日期、引用的条目

这两种页面类型都有双向反向链接到他们提到的每个实体。

## 使用的工具

- 从 gbrain 读取页面（get_page）
- 在 gbrain 中存储/更新页面（put_page）
- 在 gbrain 中添加时间线条目（add_timeline_entry）
- 按类型在 gbrain 中列出页面（list_pages）
- 在 gbrain 中存储原始 API 数据（put_raw_data）
- 从 gbrain 检索原始数据（get_raw_data）
- 在 gbrain 中链接实体（add_link）
- 在 gbrain 中检查反向链接（get_backlinks）
