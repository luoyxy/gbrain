# Ask User — 选择门模式

## 合约

- 呈现 2-4 个选项（不多 — 超过 4 个会出现决策瘫痪）。
- 始终包含逃生舱口（跳过、取消或"这些都不是"）。
- 呈现选择后立即停止回合。无后续工具调用、
  无 preemptive 操作、无默认并继续。
- 用户的响应触发下一个回合。简要确认，然后分支。
- 每条消息一个问题 — 永远不要堆叠多个选择门。
- 自解释选项标签：动作动词加上简要限定符，不是"选项1"。

## 这是什么

向用户呈现 2-4 个选项并**停止
执行**直到他们响应的**形式化模式**。这是在任意基于 GBrain 的智能体中
在选择上设置门控的规范方式。

这不是传统的 async/await。在 LLM 智能体中，"门控"意味着：
1. 呈现选择（按钮或编号选项）
2. 显式停止当前回合（不要继续）
3. 用户的响应触发下一个回合
4. 读取响应并相应分支

## 何时使用

- 具有多种有效解释的模糊请求
- 破坏性操作（批量删除、覆盖）
- 归档/路由决策（"这应该去哪里？"）
- 优先级分类（"我应该先做什么？"）
- 冷启动阶段门（"准备好下一个导入源？"）
- 错误默认会浪费大量工作的任何分支

## 何时不使用

- 清晰、明确的指令 → 直接做
- 低 stakes 决策 → 选择最佳选项并提及它
- 延迟成本高于错误选择的时间关键操作
- 当用户已经表达偏好时

## 如何呈现选择

### 平台无关格式（随处适用）

将选择呈现为带有编号或标记选项的清晰问题：

```
🔀 **我应该如何处理这个？**

[关于决策的上下文 — 最多 1-3 行]

1. **选项 A** — 简短描述
2. **选项 B** — 简短描述
3. **选项 C** — 简短描述
4. **跳过** — 现在什么都不做
```

### 带内联按钮（Telegram、Discord、Slack）

如果平台支持交互式按钮，请使用它们：

```json
{
  "message": "🔀 **我应该如何处理这个？**\n\n<上下文>",
  "buttons": [
    { "label": "选项 A — 描述", "value": "option_a" },
    { "label": "选项 B — 描述", "value": "option_b" },
    { "label": "跳过", "value": "skip" }
  ]
}
```

### 带 `clarify` 工具（OpenClaw 智能体）

一些 OpenClaw 智能体具有内置的 `clarify` 工具，可以原生呈现选择：

```
clarify(
  question: "我应该如何处理这个？",
  choices: [
    "选项 A — 描述",
    "选项 B — 描述",
    "选项 C — 描述",
    "暂时跳过"
  ]
)
```

## 约束

- **最多 2-4 个选项。** 超过 4 个会产生决策瘫痪。
- **标签必须是自解释的。** 用户不需要重新阅读上下文。
- **始终包含逃生舱口。** 至少："跳过"或"取消"作为最后一个选项。
- **每条消息一个问题。** 永远不要堆叠多个选择门。

## 如何门控（关键）

呈现选择后，你**必须停止你的回合**。不要：
- ❌ 继续"当你决定时，我将开始..."
- ❌ 选择默认并继续
- ❌ 在用户响应之前发送后续消息
- ❌ 对他们的选择做出假设

相反：
- ✅ 以你正在等待的简要说明结束消息
- ✅ 停止。完全停止。不再有工具调用。

## 如何处理响应

当用户响应时：

1. **读取响应** — 按钮点击、编号或文本
2. **简要确认** — "收到，选择选项 A。"
3. **分支并执行** 选择的路径
4. 如果不清楚，再次询问

### 处理文本响应

用户有时会键入而不是点击。优雅地处理：
- "第一个" / "A" / "1" → 映射到第一个选项
- "合并" → 模糊匹配选项标签/值
- "实际上，这些都不是" → 呈现替代方案或询问他们想要什么
- 不相关消息 → 用户继续；丢弃门

## 格式指南

### 问题行表情符号前缀

 signal 决策类型：
- 🔀 路由/归档决策
- ⚠️ 破坏性/危险操作
- 🎯 优先级/分类决策
- 💡 创意/战略分支
- 📋 工作流/流程选择
- 🔐 凭证/安全决策

### 上下文块

最多 1-3 行。用户应该在 5 秒内理解决策。

### 按钮/选项标签

格式：`动作动词 — 简要限定符`
- ✅ "合并 — 与现有页面合并"
- ✅ "创建新 — 单独的会议页面"
- ❌ "选项1"
- ❌ "点击此处将内容合并到现有大脑页面"

## 示例

### 冷启动阶段门
```
📋 **阶段2：Google 联系人**

我可以导入你的 Google 联系人以种子 people/ 目录。
这为每个真实联系人创建一个大脑页面（约 200 个页面）。

1. **通过 ClawVisor 导入** — 安全凭证网关
2. **通过直接 OAuth 导入** — 更简单，智能体持有令牌
3. **从 Google Takeout 导出导入** — 离线，从文件
4. **跳过** — 移动到下一个阶段
```

### 归档决策
```
🔀 **这应该去哪里？**

与 Jane Smith 通话的会议记录。她已经在
people/jane-smith.md 有一个页面，在 deals/acme-corp.md 有一个交易页面。

1. **合并到 Jane 的页面** — 添加到她的时间线
2. **添加到 Acme 交易页面** — 这主要是交易讨论
3. **新会议页面** — 独立在 meetings/2026-01-15-jane-acme.md
4. **跳过** — 不归档这个
```

### 破坏性操作
```
⚠️ **即将删除 847 个过期缓存文件（2.3 GB）**

这些在 90+ 天内没有被访问。它们可以重新获取
但这需要约 4 小时。

1. **删除它们** — 立即释放空间
2. **先归档** — 上传到云存储，然后删除
3. **保留它们** — 无更改
4. **给我看列表** — 让我在决定之前审查
```

## 与其他技能的集成

此模式被以下使用：
- **cold-start** — 每个导入源的阶段门
- **ingest** — 模糊内容的路由决策
- **enrich** — 实体页面的合并与创建决策
- **brain-ops** — 归档位置决策
- **meeting-ingestion** — 会议记录归档位置
- **archive-crawler** — 扫描与完全摄取门

当构建需要在决策点进行用户输入的新技能时，
引用此模式而不是发明新的。

## 反模式

- **呈现选择后继续回合。** "当你决定时，我将开始..."
  击败门。停止。等待。重点是用户控制接下来发生什么。
- **选择默认并静默继续。** 如果问题足够重要到要问，
  就足够重要到要等待。静默默认会侵蚀你下次询问时的信任。
- **超过 4 个选项。** 决策瘫痪是真实的。改为分组、总结或拆分为
  分阶段问题。
- **无逃生舱口。** 每个选择门必须让用户拒绝。"这些都不是"
  / "跳过" / "取消"是强制性的。
- **在一条消息中堆叠多个选择门。** 用户每个回合只能回答一个
  问题。多问题门要么得到半回答，要么完全丢弃。
- **隐秘选项标签。** "选项1" 强制重新阅读上下文。"合并到
  现有页面"是自解释的。
- **询问低 stakes 决策。** 如果错误答案不花费任何成本，只需
  选择最佳选项并提及它。保留门用于返工昂贵的分支。

## 输出格式

技能的"输出"是选择门消息本身，结构为：

```
{emoji-prefix} **{question}**

{1-3 行上下文}

1. **{选项 A 标签}** — {简短限定符}
2. **{选项 B 标签}** — {简短限定符}
3. **{跳过/取消}** — {跳过意味着什么}
```

发出此后，技能停止回合。在用户响应之前，不再有工具调用、no
抢占式操作、无后续消息。
用户的响应触发下一个回合，调用技能在所选选项上
分支。
