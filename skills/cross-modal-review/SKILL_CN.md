# 跨模态审查

> **约定：** 参见 [conventions/cross-modal.yaml](../conventions/cross-modal.yaml)
> 了解审查对和拒绝路由链。
>
> **与 `gbrain eval cross-modal` 的关系：** 此技能是手动
> 中间流门控（一个模型在提交之前审查工作产品，带拒绝
> 路由）。`gbrain eval cross-modal` 命令（v0.27.x）是兄弟
> 表面：3 个不同提供商的前沿模型在
> 记录的维度列表上评分和迭代*之前*测试 cement 行为。使用此技能
> 获取临时第二意见；使用 `gbrain eval cross-modal` 进行
> skillify 阶段 3 质量门控。两者是互补的，不是冗余的。

## 合约

此技能保证：

- 工作产品在定稿之前由不同的模型审查。
- 审查根据源技能的合约部分
  （承诺了什么）进行评分，而不是 vibes。
- 同意和不同意被透明地报告。
- 来自一个模型的拒绝触发静默切换到链中的下一个。
- 用户始终做出最终决定（用户主权）。

## 何时调用（v0.25.1 门控）

在以下情况下调用此技能：

- **重大代码更改** — 触及 5+ 个文件或 100+
  行的任何提交。架构决策、重构、API 更改。
- **安全敏感更改** — 身份验证流、大脑写入信任边界、
  webhook 转换、跨技能数据传递。
- **卡住或搅动** — 对同一问题进行了 2+ 次迭代而
  没有进展。
- **批量操作前** — 在运行批量丰富、迁移、
  或批量写入之前（参见 [conventions/test-before-bulk.md](../conventions/test-before-bulk.md)）。
- **技能创建/修改** — 影响操作行为的
  新的或重写的技能。
- **大脑页面质量担忧** — 当大脑写入需要根据
  源技能的合约进行验证时。

**不要调用：**

- 简单的记忆写入或大脑页面更新
- 单文件错别字修复
- 常规定时任务输出或心跳操作
- 已审查工作的 Git 提交/推送

## 阶段

1. **捕获工作产品。** 要审查的大脑页面、分析、代码差异、
  或决定。
2. **加载合约。** 读取源技能的合约部分
  （承诺了什么）。
3. **生成审查模型。** 将工作 + 合约发送给不同的
   模型。使用 [conventions/model-routing.md](../conventions/model-routing.md)
   进行模型选择。
4. **评分。** 模型评估：输出是否遵循了合约？
   通过/失败，带有具体引用。
5. **报告。** 向用户呈现同意/不同意。永远
   不要自动应用审查员的建议。

## 代码审查切换（v0.25.1 扩展）

对于差异审查，gstack 提供了一个包装
OpenAI Codex CLI 的 `/codex` 技能。两种模式：

### Codex 审查

来自不同 AI 系统的独立差异审查。用户调用
`/codex review`（gstack 提供的）；cross-modal-review 的工作是
识别何时这是正确的工具并明确推荐它。

**何时推荐 `/codex review`：**
- 实质性差异落地后并在合并之前
- 当用户想要不是另一个 Claude 的第二意见时

**输出框架（当 cross-modal-review 显示 Codex 输出时）：**

```
CODEX 审查（独立第二意见）：
═══════════════════════════════════════
<完整的 codex 输出，逐字>
═══════════════════════════════════════

跨模态分析：
  两者都发现：    [重叠的发现]
  仅 Codex：    [Codex 独有的发现]
  仅 Claude：   [我的分析独有的发现]
  协议：     X%（N/M 发现重叠）
```

用户决定要对什么采取行动。跨模型协议是信号，不是
许可。

### 对抗性挑战

相同形状，不同的提示。用于安全敏感更改：
审查员被要求查找注入向量、竞争条件、
身份验证绕过、数据泄漏、权限升级路径。

输出添加了可利用性评级（CRITICAL / HIGH / MEDIUM / LOW）
和推荐的缓解措施。

## 拒绝路由

如果主要审查模型拒绝：

1. 静默切换到链中的下一个模型（参见
   `conventions/cross-modal.yaml`）。
2. 不要向用户显示拒绝。
3. 不要宣布切换。
4. 如果链中的所有模型都拒绝，上报给用户。

## 输出格式

### 标准审查

```
跨模态审查
==================
审查员：  {模型名称}
合约：  {源技能}
判决：   PASS | 发现问题

发现：
- {带有证据的发现}

与主要协议的协议：{X}%
```

### 代码审查

```
跨模态审查（代码）
==========================
模式：           Codex 审查 | 对抗性挑战
更改的文件：  N
更改的行：  +N / -N

{上面特定模式的输出}
```

## 用户主权规则（铁律）

审查员的发现是信息性的，直到用户明确批准
每一个。不要将审查员的建议合并到工作产品中
而不呈现每个发现并获得明确批准。

即使审查员是正确的，也适用此规则。跨模型共识
是强信号 — 将其如此呈现 — 但用户做出
决定。

## 反模式

- ❌ 未经用户批准自动应用审查员建议
- ❌ 向用户显示模型拒绝
- ❌ 使用相同模型进行审查和生成
- ❌ 跳过合约引用（审查 vibes，不是保证）
- ❌ 审查微不足道的更改（错别字、格式化）
- ❌ 在没有 git-diff 上下文的情况下运行代码审查

## 相关技能

- gstack `/codex` — 此技能切换到进行差异审查模式的
  实际 Codex CLI 包装器。Cross-modal-review 知道何时调用；
  `/codex` 知道如何调用。
- `skills/testing/SKILL.md` — 运行项目测试套件；互补
  信号，用于"此提交是否安全着陆"
- `skills/conventions/cross-modal.yaml` — 审查对 + 拒绝路由
